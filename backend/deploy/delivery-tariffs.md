# Синхронизация доставки — 1.6.1+61

Saby хранит цены районов. Бэкенд читает `retail/district/list` и атомарно обновляет
DeliveryZone / DeliveryPriceTier. Неполный список, неизвестный район, дробные или
отрицательные рубли и ошибка API оставляют последние успешные тарифы без изменений.
Никакие продажи, оплаты, товары и настройки в самом Saby команда не изменяет.

## Установка на сервере

Распаковать содержимое `backend-delivery-1.6.1.zip` в существующий каталог
`/var/www/delycafe_backend/Delycafe/backend/` с заменой файлов.
Архив не содержит .env, базы данных, media и секретов. Не удалять эти каталоги.

Из активного venv в каталоге backend:

```bash
python manage.py migrate
python manage.py check
python manage.py sync_saby_delivery_tariffs --dry-run
python manage.py sync_saby_delivery_tariffs
sudo systemctl restart delycafe_backend
sudo systemctl is-active delycafe_backend
```

Сохранить существующие значения .env:

```dotenv
SABY_DELIVERY_MODE=native
SABY_DISTRICT_OZERSK=7744
SABY_DISTRICT_PROMPLOSHADKA=7746
SABY_DISTRICT_TATYSH=7745
```

В `crontab -e` пользователя delycafe добавить одну строку (если такой ещё нет):

```cron
*/5 * * * * cd /var/www/delycafe_backend/Delycafe/backend && /usr/bin/flock -n /var/www/delycafe_backend/delivery-tariffs.lock /var/www/delycafe_backend/venv/bin/python manage.py sync_saby_delivery_tariffs >> /var/www/delycafe_backend/delivery-tariffs.log 2>&1
```

Путь Python в строке должен совпасть с `which python` в активном серверном venv.
Не заменять весь crontab: другие задания нужны для сверки платежей и статусов.
При изменении цен в Saby можно сразу выполнить `sync_saby_delivery_tariffs`, не дожидаясь cron.

## Расчёт и текст

- В режиме native перед каждым созданием/повторным оформлением заказа с доставкой
  сервер заново читает Saby. Если тарифы проверить не удалось, заказ не создаётся
  и новая банковская сессия не открывается. Самовывоз не требует этой проверки.
- Бессрочный кэш тарифов в процессах Django удалён. Изменения доступны всем worker.
- Порог доставки считается от суммы товаров после скидок и списания бонусов:
  именно эти цены передаются в Saby как `cost`. Например, при товарах на 1000 ₽
  и списании 50 бонусов база доставки составляет 950 ₽. Самовывоз остаётся бесплатным.
- Первый порог Saby 50 ₽ сохраняется. Заказ ниже него не оформляется как бесплатная доставка.
- У старых/оплаченных заказов суммы не переписываются. Платёж и чек по заказам
  №173/174/177 эта синхронизация не повторяет и не исправляет.

Для автоматического текста используются метки:

```text
{{delivery_tariff:ozersk}}
{{delivery_tariff:promploshadka}}
{{delivery_tariff:tatysh}}
```

Их можно вставить в «Описание в оформлении заказа» нужной зоны и в текст блока
«Доставка и оплата». До выдачи API метка заменяется актуальными ценами/порогами;
приложения прежних версий получают обычный готовый текст. Остальные абзацы,
время доставки, телефоны и способы оплаты не меняются при обновлении цен.

Миграция автоматически заменяет стандартные исходные описания на метки, включая
пояснение про промплощадку. Если тексты раньше редактировались вручную, они
сохраняются; команда предупреждает о таких описаниях. Один раз заменить в них
только перечисление цен соответствующей меткой, сохранив остальные пояснения.
Не вписывать новую цену вручную рядом с меткой: она станет устаревшей при следующем изменении.

## Приложение

Новая сборка обновляет условия при открытии оформления, страницы доставки,
возврате из фона и непосредственно перед отправкой заказа. Ошибка сети не
заменяет ранее загруженные тарифы встроенными значениями. Перед оформлением
свежая загрузка обязательна. Если сумма изменилась при обновлении или сервер
рассчитал другой итог, приложение показывает старую/новую суммы и требует
подтверждения до открытия страницы оплаты. Отказ сохраняет корзину.

API сохраняет прежние поля. Старые приложения работают, но их экран оформления
может показывать старый кэш или считать порог до бонусов. Окончательную сумму
по-прежнему определяет сервер; новый диалог подтверждения есть только в 1.6.1.

## Проверка после установки

1. Открыть `/api/orders/delivery-config/`: описания должны содержать рубли,
   без меток `{{...}}`, а `price_basis` — `after_discounts`.
2. Проверить Озёрск на обеих сторонах 1000 и 2000 ₽, а также списание бонусов,
   которое переводит сумму товаров через порог. Проверить промплощадку и Татыш.
3. После следующего настоящего заказа: `python manage.py inspect_saby_totals НОМЕР`.
   Сумма Saby должна совпасть с оплатой, без отдельной дублирующей позиции доставки.
   Наличие фискального документа проверяется отдельно в ОФД.

Тарифы в Saby могут измениться уже после открытия банковской страницы. Такие
сессии сохраняют прежнюю сумму: синхронизация не может поменять уже одобренную
клиентом оплату. Сверка перед регистрацией чека остаётся включена и остановит
регистрацию при расхождении. Менять тарифы лучше вне приёма заказов, когда нет
незавершённых оплат. Реальную печать после обновления нужно проверить на кассе.

Официальная структура API: https://saby.ru/help/integration/api/app_presto/Presto_delyvery/districts

Android APK собирается с текущими настройками подписи проекта (release использует
debug signingConfig). Публикацию в Google Play/App Store эта сборка не выполняет.
Для iOS нужен отдельный архив в Xcode на macOS.
