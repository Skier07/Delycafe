# Адаптивные фотографии товаров

## Что меняется

Загружаемый оригинал хранится без изменений. Backend при загрузке обложки или фотографии галереи создаёт WebP quality=90 с максимальной стороной 1254 и 3840. Прозрачность, включая полупрозрачную тень, сохраняется. Пропорции сохраняются; квадратный оригинал даёт квадратные версии. Маленькие исходники не увеличиваются: для оригинала 1254 существует только версия 1254. Поэтому настоящие оригиналы 3840×3840 нужно подготовить отдельно — этот механизм не добавляет детали.

API сохраняет прежние `image`/`images` и добавляет `image_variants`: словарь URL оригинала → список `{url, width, height}`. Старые приложения продолжают работать. Каталог GET не выполняет конвертацию файлов.

Flutter выбирает минимальную достаточную версию по размеру изображения в виджете × плотности пикселей с учётом contain/cover. Например, фото 320 логических пикселей при DPR=3 использует 1254, фото 717 при DPR=2 использует 3840. Наличие большого экрана само по себе не заставляет маленькую плитку загружать большой файл. Это не определение мощности процессора телефона.

В дисковый кэш CachedNetworkImage скачивается выбранный WebP; декодирование в RAM ограничено требуемым размером. При необходимости разных размеров на одном устройстве могут храниться обе версии. Действуют стандартные пределы существующего flutter_cache_manager: до 200 объектов, удаление неиспользуемых после 30 дней. Это ограничение числа файлов, не строгий лимит в мегабайтах; ОС также может очищать кэш. URL версии содержит SHA-256 оригинала, поэтому замена фото меняет ключ кэша. Старый каталог без вариантов работает как раньше, с ограничением размера декодирования.

## Установка

Обновить изменённые файлы catalog, включая миграцию 0012, и клиент Flutter. В активированном серверном venv из backend выполнить:

```sh
python manage.py migrate
python manage.py prepare_product_images
sudo systemctl restart delycafe_backend
```

Миграция обязательна ДО перезапуска процесса с новым кодом. Команда готовит версии ранее загруженных фото; её можно повторять. Для одного товара: `python manage.py prepare_product_images --product-id 69`. Ошибки отдельных фото выводятся; команда продолжает обработку и завершится ненулевым кодом, если есть ошибки. Прежде чем включать новую сборку приложения, исправить такие ошибки и повторить команду.

Новые фото из админки обрабатываются автоматически. Создание WebP занимает время при сохранении фотографии; выполняется на сервере, не на телефоне. При ошибке генерации товар сохраняется с оригинальным URL, ошибка попадает в лог, варианты можно восстановить командой. Не следует массово загружать сотни 4K-фото одним HTTP-запросом: команды пакетной подготовки удобнее для такого объёма.

Убедиться, что nginx раздаёт весь MEDIA_ROOT, включая products/renditions/, а Pillow собран с WebP. После установки новой Flutter-сборки обновить каталог. Проверить маленькую плитку, детальную карточку и галерею на телефоне/планшете. Серверный код и мобильная сборка в этой задаче автоматически не развёртывались.

Старые производные файлы на сервере автоматически не удаляются: они могут ещё использоваться клиентами с закэшированным каталогом. Их очистка требует отдельной политики хранения.
