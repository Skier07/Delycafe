# Обновление безопасности 1.6.2+62

Подготовлены исходники Flutter и Django. APK/IPA не собирались и сервер не изменялся.

## Совместимость и порядок выпуска

Новый протокол входа требует обновления приложения и бэкенда. Уже выданные действующие токены продолжают работать; отключённые аккаунты доступа не получают. Старые сборки после обновления сервера не смогут заново войти по SMS/Mobile ID: завершение входа без секрета устройства закрыто. Незавершённые сессии входа нужно начать заново.

Оформление заказа теперь требует авторизации. На гостевом баннере скрыты правые кнопки меню и корзины; при переходе к оформлению другим путём приложение предлагает войти. Каталог доступен для просмотра.

Подготовьте и проверьте новую сборку до переключения рабочего бэкенда. Для публикации в магазинах учитывайте время проверки и распространения обновления; старый вход нельзя временно включать обратно ради совместимости.

## Что загружать через WinSCP

Архив `build/security-release/backend-security-1.6.2.zip` содержит изменённые файлы с путями от корня проекта. Его каталог `backend/` соответствует `/var/www/delycafe_backend/Delycafe/backend/` на сервере. Список файлов лежит в `FILES.txt` внутри архива.

Загрузите файлы с заменой соответствующих файлов проекта. `.env`, `media/`, база данных и виртуальное окружение в архив не включены. Папки с изображениями не удаляйте. Удаление локальных SQLite-файлов из индекса Git не означает удаление файлов сервера.

Обязательные новые миграции:

- `customers/migrations/0010_phoneauthsession_security.py`: секрет и однократное потребление сессии входа, отметка отзыва токенов клиента.
- `orders/migrations/0017_checkout_idempotency.py`: идентификатор повторяемого запроса оформления.

## Настройки сервера

Сохраните действующий `.env`. В рабочем окружении `SMSAERO_ENABLED=true` и действующие настройки SMS Aero обязательны для обычного входа. При выключенной SMS-службе production больше не принимает тестовый код `1234`.

Демо-вход App Review включается только явно заданными `APP_STORE_REVIEW_PHONES` и `APP_STORE_REVIEW_CODE`. Используйте отдельный демо-аккаунт и приватный код, сообщённый проверяющим Apple. Пример: `backend/deploy/appstore-review.env.example`.

При использовании Mobile ID проверьте общий секрет webhook: `SMSAERO_WEBHOOK_SECRET` должен совпадать с настройкой отправителя. Номер из webhook должен соответствовать сессии.

HTTPS redirect включён по умолчанию в production. Nginx должен завершать TLS и передавать `X-Forwarded-Proto: https` в Django; прямой внешний доступ к Gunicorn нужно закрыть. Иначе возможен цикл перенаправления. Настройки: `DJANGO_SECURE_SSL_REDIRECT=true`, `DJANGO_SECURE_HSTS_SECONDS=3600`. HSTS для всех поддоменов и preload автоматически не включены.

Режим доставки оставьте `SABY_DELIVERY_MODE=native`, с существующим сопоставлением районов. Пороги по-прежнему рассчитываются по стоимости товаров после скидок и списания бонусов.

## Команды после загрузки

Сначала сделайте штатную резервную копию PostgreSQL и `.env`. Затем из папки backend, с активированным существующим venv:

```bash
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py check
python -c "import django; print(django.get_version())"
python manage.py sync_saby_delivery_tariffs
sudo systemctl restart delycafe_backend
sudo systemctl is-active delycafe_backend
```

Ожидаемая версия Django — `6.0.9`. Для production можно отдельно выполнить `python manage.py check --deploy` и проверить предупреждения относительно фактической конфигурации Nginx/TLS.

Обновите действующий crontab по `backend/deploy/cron.example`. Особенно важна команда `expire_stale_unpaid_orders`: она сверяет старые банковские сессии и возвращает резерв бонусов только при подтверждённом завершении неоплаченной сессии. Загрузка файла-примера сама по себе расписание не устанавливает.

## Оплаты и бонусы после обновления

Изменение корзины больше не отменяет предыдущий неоплаченный заказ. Пока банк допускает оплату старой ссылки, списанные при оформлении бонусы остаются зарезервированными. Завершение банковской сессии обрабатывает проверка статуса/cron.

Новая сборка сохраняет идентификатор оформления в защищённом хранилище. Повтор того же запроса после таймаута возвращает тот же заказ без повторного списания. Уже оплаченный ответ закрывает оформление без повторного открытия оплаты.

Все подтверждения оплаты сверяют номер заказа, сумму, валюту, возвраты и ID банковской сессии, если он присутствует в ответе. Отрицательный callback также проверяется в банке; он не может самостоятельно понизить оплаченный заказ до ошибки.

Если поздняя оплата поступит по исторически отменённому заказу с уже возвращёнными бонусами, деньги фиксируются как оплаченные, но автоматическая отправка в Saby и повторное начисление бонусов блокируются. В заказе появляется `saby_payment_error` с требованием ручной сверки. Найти такие случаи можно в админке по сочетанию «Оплачен» и «Отменён», а также по журналу `Late payment requires manual reconciliation`. После сверки оператор принимает решение об исполнении или возврате; обновление само деньги не возвращает и старые чеки заново не создаёт.

## Android в VSCode

Версия исходников — `1.6.2+62`. Для release больше нет неявной подписи debug-ключом. Скопируйте `android/key.properties.example` в `android/key.properties` и укажите существующий ключ подписи и его параметры. Настоящий файл и keystore исключены из Git.

Для установки поверх опубликованного APK требуется прежняя подпись либо предусмотренный магазином механизм смены ключа. Не создавайте новый ключ наугад. Если предыдущие APK подписаны debug-ключом, сначала определите способ миграции; автоматической смены сертификата в этих правках нет. Явный Gradle-параметр `-PallowDebugSigning=true` предусмотрен только для локальной проверки и не является настройкой публикации.

## Платёжный WebView

Карточная оплата с самого начала открывается во внешнем браузере: он сохраняет всю сессию и POST-переходы 3DS. Приложение проверяет результат через бэкенд при возвращении и по таймеру. При повторном открытии используется та же платёжная ссылка. СБП сохраняет экран выбора банка внутри приложения и переход в банковское приложение.

Внутри WebView разрешены HTTPS-адреса шлюза и точные return URL вашего API. Произвольные адреса со словами `alfabank`, `acs` или `3ds` доверенными не считаются. Дополнительные проверенные ACS-хосты для встроенного сценария можно указать при сборке через `PAYMENT_3DS_ALLOWED_HOSTS` (точные имена через запятую); карточная оплата от этого списка не зависит.

На тестовом контуре эквайринга проверьте карту с 3DS и СБП с установленным/неустановленным банковским приложением. Реальные платежи, SMS и внешние записи в Saby в локальных проверках не выполнялись.

Логи итоговых локальных проверок находятся в `build/security-fixes-backend.log`, `build/security-fixes-flutter.log` и `build/security-fixes-analyze.log`. Работа advisory-lock синхронизатора в реальном PostgreSQL и доставка физического чека требуют проверки в серверном окружении.
